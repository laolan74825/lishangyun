# 手机号注册改造实现说明

> 日期：2026-10-10　版本：v0.3.0　关联文档：`docs/2026-10-09-手机号注册与APK推广实施方案.md`、`docs/用户管理需求规划.md`

## 一、改造内容

### 注册流程（核心变更）

| 项目 | 改造前 | 改造后 |
|---|---|---|
| 身份校验 | 主安全邮箱 + 邮箱验证码（必填） | 手机号 + 短信验证码（必填） |
| 安全邮箱 | 必填，注册即验证 | 选填，注册阶段不验证，记入未验证状态 |
| 备用安全邮箱 | 可填第 2 个 | 移除（设置页后续仍可绑定多个） |
| 用户名唯一 | 数据库唯一索引（500 兜底） | 预检 409「该用户名已被使用」+ 索引兜底 |
| 手机号唯一 | 无 | 必填 + 数据库唯一索引 + 预检 409「该手机号已被注册」 |

接口变化：`POST /api/auth/register` 请求体改为 `{username, password, nickname?, phone, phone_code, security_email_1?}`；
原 `security_email_1_code` / `security_email_2` / `security_email_2_code` 字段移除。
新增 `POST /api/auth/send-sms-code`，请求体 `{phone}`。

### 短信通道

`server/app/core/sms.py` 用 Python 标准库实现阿里云 SendSms 的 POP RPC 签名（HMAC-SHA1），
**不引入 SDK 依赖**。配置存数据库 `system_settings` 表（与 SMTP 相同机制）：

| key | 说明 |
|---|---|
| `sms_mode` | `mock`（只记日志，不发短信）或 `aliyun`（真实发送），缺省视为未配置 |
| `sms_access_key_id` | 阿里云 AccessKey ID |
| `sms_access_key_secret_enc` | AccessKey Secret（AES 加密存储） |
| `sms_sign_name` | 短信签名（须与阿里云审核通过的一致） |
| `sms_template_code` | 模板 CODE（模板须含 `${code}` 变量） |

验证码规则与邮箱通道一致：6 位数字、10 分钟有效、一次性使用、同号 60 秒重发节流。

## 二、运维操作

### 开发联调（Mock 模式）

1. 管理后台 → 系统设置 → 短信服务配置 → 发送模式选 **Mock** → 保存。
2. 注册页点「发送验证码」，验证码不发短信，直接看服务端日志：

```bash
docker compose logs -f api   # 找 【Mock短信】向 138… 发送验证码 123456
```

### 切换阿里云真实短信

前提：阿里云短信服务已开通、签名与验证码模板**审核通过**。

1. 管理后台 → 系统设置 → 短信服务配置：
   - 发送模式改 **阿里云**
   - 填 AccessKey ID / Secret（建议用仅授权 SMS 权限的子账号 Key）
   - 填签名名称与模板 CODE → 保存
2. 用真实手机号注册验证一次，收不到就看 `docker compose logs api` 里的错误码。

### 数据库迁移

迁移 m11（`l3m4n5o6p7q8_add_phone_registration`）：
`users` 加 `phone` 列（唯一索引，可空，存量用户为 NULL 不受影响）+ 新建 `phone_verification_codes` 表。
容器启动时 alembic 自动执行，无需手工操作。

### 数据迁移注意

`system_settings` 里的短信/SMTP 配置跟着数据库走。备份恢复到新环境后配置一并带走；
全新部署需重新配置（本文件第二节即操作手册）。

## 三、阿里云个人用户备案提示

按 `docs/2026-10-09-手机号注册与APK推广实施方案.md` 的结论：
标准短信服务的自定义签名对个人身份收紧，个人开发者优先走阿里云「短信认证」
（系统预置签名 + 标准模板，免签名审核）；若注册了个体户/公司执照，可切换标准短信
服务并使用自定义签名「礼尚云」。本实现兼容两种——只要拿到 AccessKey 与模板 CODE，
在管理后台填入即可，代码无需改动。
