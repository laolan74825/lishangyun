# 2026-10-09 手机号注册改造与 APK 推广实施方案

背景：项目当前以「安全邮箱 + 验证码」为注册与找回密码的唯一途径，手机上操作邮箱不够顺手。为推广给陌生用户（设备不可控），确定走「手机号注册/绑定 + 打包 APK」路线。本文档为完整操作方案与成本预算。

## 一、方案概述

把「安全邮箱验证码」体系改造为「手机号 + 短信验证码」为主、邮箱降级为可选项：

- **注册**：手机号 + 短信验证码 + 设置密码（邮箱改可选）
- **登录**：手机号 + 密码（用户名登录保留）
- **找回密码**：短信验证码重置（不再依赖邮箱）
- **设置页**：绑定/换绑手机
- **防刷保护**：60 秒重发限制、单号日上限、单 IP 日上限、图形验证码兜底——短信按条收费，防刷是验收红线

## 二、实施步骤

### 第 0 步：基础设施采购与备案（周期最长，最先启动）

| 事项 | 说明 | 周期 |
|-|-|-|
| 买云服务器 | 腾讯云/阿里云轻量应用服务器 2核2G3M，约 99 元/年 | 当天 |
| 买域名 | `.com` 或 `.cn`，约 30-60 元/年 | 当天 |
| ICP 备案 | 云厂商免费代办，需服务器在国内 | **1-3 周** |
| 注册阿里云 + 开通「短信认证」 | 个人实名认证即可，免资质/签名/模板申请 | 当天 |

**短信选型关键政策（2025-09 起）**：工信部要求短信签名实名报备，运营商不再接受个人身份的自用资质。腾讯云与阿里云的标准短信服务实际只对企业资质开放；**阿里云「短信认证」（号码认证服务旗下）专为个人开发者设计：免资质、免签名模板申请，用系统预置签名 + 标准验证码模板直接 API 调用，发送失败不计费**。代价是签名不能自定义、只能发验证码类内容。若有个体户/公司执照，可走标准短信服务自定义「礼云随笔」签名。

注意：ICP 备案没下来之前公网站点不能开放访问；开发和内网测试不受影响，可以先写代码。备案是全程最长的单线程任务，应最先启动。

### 第 1 步：后端改造（开发 3-5 天）

3. 新增短信发送接口（接入阿里云「短信认证」SDK），含频控与上限
4. 注册接口改造：手机号 + 验证码 + 密码；登录接口支持手机号
5. 找回密码流程整体切到短信
6. 设置页绑定/换绑接口
7. 后端测试补齐：验证码场景的频控、伪造、过期用例

### 第 2 步：前端改造（开发 2-3 天）

- 注册页：手机号输入 + 发送验证码
- 登录页：支持手机号输入
- 密码重置页：改为手机号流程
- 设置页：手机绑定管理
- 现有前端测试（189 条）同步调整

### 第 3 步：上云部署（1 天）

项目已有 Docker Compose 全套：装 Docker → 拉代码 → 改环境变量（数据库密码、短信密钥）→ `compose up`，Caddy/nginx 自动 HTTPS 证书（Let's Encrypt 免费）。

### 第 4 步：APK 打包与内测（ICP 备案完成后）

Capacitor 集成 → 出调试包 → 亲友内测 → 修问题。

## 四、技术选型备忘

- **APK 壳：Capacitor**。现有 React 前端原样打包进 APK，只加原生壳（约 10MB），系统 WebView 渲染；Cordova 已过时，uni-app/Taro 重写代价过大
- **短信：阿里云「短信认证」**（个人无执照场景）。免资质签名模板，系统预置签名；若日后有个体户/公司执照，可平滑切换到标准短信服务自定义签名
- **内核约束**：APK 用系统 WebView 内核，现代手机 WebView 可自动更新，目标用户不受旧内核困扰；此前为旧浏览器做的 es2018 降级与 polyfill 保留作保险，不撤销

## 五、风险与提醒

1. **短信防刷是红线**：不加频控和上限，被恶意调用一天可烧掉数百元。三层限制（重发间隔/单号日上限/IP 日上限）作为验收标准
2. **ICP 备案最长**：建议当周内下单服务器和域名提交备案，开发与备案并行
3. **短信签名限制**：个人无执照场景走阿里云「短信认证」，只能用系统预置签名（非「礼云随笔」），属合规接受的代价；若对品牌露出敏感，可注册个体户后切换标准短信服务
4. **数据库端口安全**：上云时数据库不得对外暴露端口，仅容器网络内可达
