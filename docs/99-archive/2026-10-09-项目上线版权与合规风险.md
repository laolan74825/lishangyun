## 1. 产品简介

礼云随笔是一款面向个人和家庭的轻量级礼金往来管理工具，覆盖完整的随礼生命周期：

- **日常记账**：记录每一次送出或收到的礼金，掌握人情往来差额，提醒回礼时机。
- **宴请收礼**：现场快速创建礼簿，支持多人同时用手机/平板记账，实时同步，确保账目安全。
- **合并归档**：宴席结束后通过合并向导建立人员关联，计算往来差额，礼簿长期保留可按宴请查看。
- **家庭共享**：创建家庭组，邀请家人共享数据，主账户审批确保数据质量。
- **双安全模式**：默认普通安全（零摩擦）；可选增强安全（客户端零知识加密，密钥不离开设备）。

支持手机、平板、电脑三端使用，支持离线记账和 PWA 安装到主屏。

## 二、GitHub 私有仓库：基本安全，已核实关键点

我检查过，做得比较好的部分：

- `.env` **从未被提交过**（全部历史中检索无记录），`.gitignore` 覆盖了密钥、数据库、日志、构建产物。
- `server/.env.example` 只含占位符，且代码里有 fail-fast 机制：生产环境用默认密钥启动会直接报错。
- 被跟踪的文件里没有密钥、证书、真实数据库文件。

**但"私有仓库"不等于绝对安全**，边界在账号本身：

- 务必给 GitHub 账号开启两步验证（2FA），用 fine-grained PAT 而非账号密码推代码。
- 在仓库 Settings 里启用 **Secret scanning** 和 **Push Protection**（免费版就有），将来误推密钥会被当场拦截。
- 私有仓库对 GitHub 平台自身不是保密的（员工在极端情况下可访问），所以真正的密钥策略是：任何密钥进过仓库（哪怕一分钟），就视为泄露并立即轮换。
- 定期审查 Collaborators，移除不再需要访问的人。

另外提醒：上面说的两张个人照片现在就在 Git 历史里，这也是建议尽快清理的原因之一。

## 三、其他法规问题：取决于你怎么"上线"

这款产品是礼金记账 + 家庭共享工具，没有支付、没有公开社交、没有 UGC 内容发布，天然避开了支付牌照、内容审核这类重监管。但**如果你打算把它作为公开网络服务对外运营（陌生人可注册）**，按中国大陆法规需要注意：

| 事项 | 要求 | 紧迫度 |
|---|---|---|
| ICP 备案 | 用国内服务器 + 域名对外提供服务，必须备案；若收费运营还需 ICP 许可证 | 上线前必须 |
| App 备案 | 若打包上架国内应用商店，需工信部 App 备案（2023 年起施行） | 上架前 |
| 个人信息保护法（PIPL） | 你收集了用户手机号（登录验证码）、亲友姓名、礼金金额等个人信息：需要隐私政策、告知同意、最小化收集，并提供账号注销/数据删除渠道 | 对外运营前 |
| 等保 2.0 | 作为网络运营者理论上有定级备案义务，小型个人应用实践中较少被强制，但规模做大后应补 | 中期 |
| 短信服务 | 发验证码的签名和通道需要实名报备，用正规云厂商服务即由其代管 | 上线时 |

如果只是**自部署给家庭和小范围亲友使用**，上述基本都不触发，PIPL 也允许为个人或家庭事务处理个人信息，风险很低。

**不是 PAT。** 当前项目推送用的是 OAuth 令牌，具体判断依据：

| 特征 | 你的凭据 | 含义 |
|---|---|---|
| 用户名 | `laolan74825` | 你的 GitHub 账号 |
| 令牌前缀 | `gho_` | **OAuth 访问令牌**（GitHub 官方应用授权流程签发） |
| 长度 | 40 字符 | 与 OAuth 令牌格式一致 |

对照：GitHub 个人访问令牌是 `ghp_` 开头（经典 PAT）或 `github_pat_` 开头（细粒度 PAT，82 字符）。`gho_` 是 Git Credential Manager（GCM，Git for Windows 自带的凭据管理器）在你首次推送、浏览器授权登录时自动签发的 OAuth 令牌，存在 Windows 凭据管理器里。

**这对安全性意味着什么：**

- 这是 GitHub 官方推荐的方式，令牌由 GCM 托管、可刷新，比手工创建长期 PAT 更省心，泄漏面也更小（不经过剪贴板、不写在配置文件里）。
- 它的权限范围跟你的账号权限等同，仓库转公开或新增协作者时同样有效——所以之前清单里"开启 2FA"那条依然重要，账号失陷 = 令牌失陷。
- 想查看或吊销：GitHub 网页 → Settings → Applications → Authorized OAuth Apps → "Git Credential Manager"，可随时 Revoke；吊销后下次推送会重新走浏览器授权。

**什么时候才需要换成 PAT：** 只有在你想让某个自动化工具（CI 脚本、定时任务等）以你的身份访问仓库时才值得创建细粒度 PAT——日常推送用现在这个 OAuth 令牌就是最佳实践，无需更换。
