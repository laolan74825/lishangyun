## 1. 测试概述

### 1.1 测试目标

确保"礼尚云"在日常记账、宴请现场收礼、家庭共享三种模式下数据准确、同步实时、资金可追溯、操作便捷。重点验证：

- 多客户端协作下的数据一致性与冲突解决
- 微信限额预警逻辑与金额精度（全链路 Integer 分单位）
- 礼簿三态生命周期（active → closing → archived）
- 用户认证安全（bcrypt → Argon2 渐进迁移、登录锁定、JWT）
- 数据隔离（owner_id 过滤）与隐私记录（is_private）
- 家庭共享审批流程与通知系统
- 授权码机制与协作权限控制
- 智能合并推荐的准确性
- 数据导入导出的完整性与校验规则

### 1.2 测试范围

**功能测试（13 个模块）：**

1. 用户认证与安全
2. 日常礼金记录 CRUD
3. 礼簿生命周期管理
4. 现场收礼（含代理送礼）
5. 对账管理
6. 操作日志与审计
7. 人员管理
8. 收款账户管理
9. 家庭共享与审批
10. 通知系统
11. 授权码与协作
12. 数据导入导出
13. 智能合并与归档

**非功能测试：**

- 性能（3000+ 条记录渲染、同步并发、API 响应 <200ms）
- 兼容性（iOS/Android/Web/PWA、平板横屏）
- 安全性（数据隔离、密码安全、防篡改、双安全模式）
- 易用性（大字模式、现场操作流程、锁屏交互）

**专项测试：**

- 离线弱网测试、UUID 幂等写入、金额边界值、登录锁定、隐私记录隔离

## 3. 核心功能测试用例

### 3.1 模块 1：用户认证与安全

**重点：** 注册登录、JWT 机制、密码安全、登录锁定、锁屏、数据隔离。

| ID | 优先级 | 测试场景 | 预期结果 |
| :--- | :--- | :--- | :--- |
| TC-1.1 | P0 | **注册-必填校验** | 用户名/密码为空或格式错误时返回 422。密码长度不足时拦截。 |
| TC-1.2 | P0 | **密码安全存储** | 数据库中 password_hash 为 bcrypt 哈希值（当前实现），非明文。相同密码两次哈希结果不同（盐值不同）。未来迁移 Argon2 后同理。 |
| TC-1.3 | P0 | **登录-JWT 签发** | 正确凭证登录返回有效 JWT token（含 user_id、role）。错误凭证返回 401。 |
| TC-1.4 | P0 | **数据隔离-owner_id** | 用户 A 创建的数据，用户 B 的 API 请求不可见（列表返回空、详情返回 404）。所有 11 个路由文件均需验证。 |
| TC-1.5 | P0 | **角色权限-5 级体系** | super_admin 可访问管理接口；user 访问 admin 接口返回 403；family_member 受家庭组权限约束；collaborator 受授权码权限约束。 |
| TC-1.6 | P0 | **token 过期** | JWT 过期后（默认 1440 分钟）返回 401，需重新登录。 |
| TC-1.7 | P0 | **登录失败锁定** | 连续 5 次登录失败后，账户锁定 30 分钟。锁定期间正确密码也返回 401 并提示"账户已锁定"。 |
| TC-1.8 | P1 | **安全邮箱绑定** | 注册时绑定 1-2 个安全邮箱，发送验证邮件。密码重置通过安全邮箱验证码（6 位，10 分钟有效）。 |
| TC-1.9 | P1 | **锁屏交互** | 不活跃后自动锁屏，显示模糊背景 + 脱敏用户名 + 密码输入框。解锁后恢复当前页面。 |
| TC-1.10 | P1 | **管理员不可重置密码** | admin/super_admin 无法重置其他用户密码，仅用户本人通过安全邮箱验证。 |
| TC-1.11 | P2 | **账户注销** | 用户申请注销后，数据保留 60 天再物理删除。注销确认弹窗明确提示保留期限。 |

### 3.2 模块 2：日常礼金记录 CRUD

**重点：** 金额精度、收支方向、人员关联、隐私标记。

| ID | 优先级 | 测试场景 | 预期结果 |
| :--- | :--- | :--- | :--- |
| TC-2.1 | P0 | **金额单位验证** | 后端接收分为单位 Integer（如 10000 = ¥100.00）。数据库无浮点数。前端展示正确转换为元。 |
| TC-2.2 | P0 | **金额范围校验** | 金额 < 100 分（¥1）或 > 10,000,000 分（¥100,000）时返回 422。Pydantic Field(ge=100, le=10000000)。 |
| TC-2.3 | P0 | **新增记录-必填校验** | 缺少金额、姓名、事由时返回 422。金额为负数或非数字时拦截。 |
| TC-2.4 | P1 | **收支方向与收款方式** | "收进来"可选 cash/wechat/other；"送出去"不显示收款方式选项，payment_account_id 为 null。 |
| TC-2.5 | P1 | **人员库联动** | 输入姓名时联想已有人员；选择后自动填充关系标签。新建人员时自动存入人员库。 |
| TC-2.6 | P1 | **差额计算验证** | 人员详情中 `净差额 = 总收到 - 总送出`，包含日常记录和已合并的礼簿记录。使用 DB 层 func.sum 聚合。 |
| TC-2.7 | P1 | **隐私记录标记** | is_private=true 的记录仅本人可见，家庭成员不可见。统计时仅计入本人数据。 |
| TC-2.8 | P1 | **软删除** | 删除记录后 is_deleted=true + deleted_at 设置。30 天后物理删除。已删除记录不出现在列表中。 |
| TC-2.9 | P2 | **分页查询** | 默认 20 条/页，最大 100 条。响应格式：`{items: [...], pagination: {page, page_size, total_count, total_pages}}`。 |
| TC-2.10 | P2 | **排序** | 支持 sort_by + sort_order（asc/desc，默认 desc）。验证按日期、金额排序正确。 |

### 3.3 模块 3：礼簿生命周期管理

**重点：** 三态流转、主办人管理、授权码生成。

| ID | 优先级 | 测试场景 | 预期结果 |
| :--- | :--- | :--- | :--- |
| TC-3.1 | P0 | **状态流转-active → closing** | active 状态可转为 closing（可逆）。closing 状态可回退到 active。 |
| TC-3.2 | P0 | **状态流转-closing → archived** | closing 可转为 archived（不可逆）。archived 不可再录入记录、不可回退。 |

| TC-3.4 | P1 | **多主办人** | guestbook_hosts 表支持多主办人（UNIQUE(guestbook_id, person_id)）。host_person_id 为主办人快速查找字段。 |
| TC-3.5 | P1 | **授权码生成** | 礼簿 owner 可为他人生成 GR-XXXXXX 格式授权码，指定权限（record/reconcile/both）和过期时间。 |
| TC-3.6 | P1 | **协作会话有效期** | 协作码 24 小时有效。最多 10 个并发客户端。归档 7 天后会话数据清理。 |
| TC-3.7 | P2 | **礼簿列表分页** | 礼簿列表支持分页、按创建时间倒序。显示状态标签（active/closing/archived）。 |

## 6. 缺陷管理标准

| 等级 | 定义 | 示例 |
| :--- | :--- | :--- |
| **P0 (致命)** | 数据丢失、资金计算错误、数据隔离失效、应用崩溃 | 合并后金额不对；离线数据丢失；用户 A 看到用户 B 数据；UUID 幂等失效 |

| **P3 (轻微)** | 建议性问题、文案错误 | 提示语错别字；按钮间距不均；排序图标方向错误 |

## 7. 风险评估与应对

| 风险 | 可能性 | 影响 | 应对措施 |
| :--- | :--- | :--- | :--- |
| **owner_id 过滤遗漏** | 中 | 高 | 46 处过滤点逐一编写隔离测试；新增 API 强制 review |

## 8. 测试执行建议

1. **自动化优先级**：P0 用例 100% 自动化；P1 用例 ≥ 80% 自动化；P2 可手动。
2. **关键模块重点**：合并逻辑（mergeWizard）、同步引擎（syncEngine）、审批流程（pending_approval）逻辑最复杂，优先编写单元测试 + 集成测试。
3. **后端先行**：当前后端 57 个路由处理器已实现，优先编写 API 测试覆盖所有端点。
4. **前端按需**：前端测试基础设施待搭建，优先覆盖 stores（Zustand）、hooks（TanStack Query）、utils（金额格式化）。
5. **用户体验测试**：现场收礼强调"大字、少步"，邀请非技术人员在模拟嘈杂环境下操作，观察录入速度和错误率。
6. **数据备份**：PWA 实现定期自动导出备份，防止清除浏览器缓存导致数据丢失。
7. **CI 门禁**：PR 合并前 P0 测试必须全部通过；覆盖率不低于 70%。
