# 2026-10-08 首页与登录页审查修复汇总

起因：对项目首页（登录后 `/` → DashboardPage）、登录页（LoginPage）、礼簿管理页（GuestbookPage）、人员管理页（PeoplePage）和账户管理页（AccountsPage）做了一轮审查，按 P1 → P3 优先级实施。遗留的"首页 N+1 请求"优化一并完成（复用既有批量接口，无需后端改动）。前端测试全绿（180 条），TypeScript 类型检查通过。

## 一、首页（DashboardPage）

### P1 正确性

- **日期边界移入组件**：原 `thisMonthStart` 等 4 个模块级常量在应用加载时计算一次，SPA 标签页常驻不刷新时跨月/跨年"本月、本年"汇总静默错位；已改为组件内 `useMemo` 按渲染时计算
- **金额统一 `formatFen`**：礼簿汇总原 `(total_amount / 100).toFixed(0)` 直接丢弃"分"位（¥123.45 显示成 ¥123），最近收款与日常记录也手写 `/100).toFixed(2)`；三处已统一走 `formatFen`（带负号处理）

### P2 体验

- **加载态解耦**：原 `gbLoading || dailyLoading` 任一未完成即整体替换为"加载中…"，统计卡片数据已返回也被挡住；改为各区块独立加载，统计卡片未就绪时显示占位"—"，两个列表各自显示加载态
- **空状态引导**：「暂无进行中的礼簿」「暂无记录」从纯文字改为带可点击的「＋ 新建礼簿」「＋ 记一笔」按钮
- **N+1 请求消除**：进行中的礼簿原逐个调用单簿 summary 接口（最多 3 次额外请求），改为一次 `GET /guestbooks/summaries` 批量查询（复用既有 `useAllGuestbookSummaries` hook），首页请求数从最多 8 个降到 6 个；协作邀请保持独立 30s 轮询不变

### P3 性能与无障碍

- **定时器空转**：`PendingInvitesBanner` 的 1 秒倒计时 interval 原在 `invites.length === 0` 时也在跑，改为按是否有邀请启停
- **移动端断点**：本月收支卡片原写死 `grid-cols-3`，窄屏拥挤；改为 `grid-cols-1 sm:grid-cols-3`
- **aria 补全**：邀请码输入框补 `aria-label` 与 `autoComplete="one-time-code"`；「合并」按钮补 `aria-label`（原仅有 `title`，移动端不可见）
- 补充说明：全局 `staleTime: 30s` 此前已配置，本次审查确认无需改动

## 三、礼簿管理页（GuestbookPage）

同一审查流程覆盖礼簿列表页与新建礼簿页，按 P1 → P3 实施。

### P1

- **Card 组件提取**：原 `Card` 定义在 `GuestbookListPage` 函数内部，每次渲染都产生新组件类型，React 卸载并重建所有卡片的 DOM 子树（hover 动画重置、状态丢失）。已提取为组件外的 `GuestbookCard`，删除/邀请/恢复回调以 props 传入
- **金额统一 `formatFen`**：卡片金额原手写 `toFixed(2)`（首页收敛时漏改的一处），已改用 `formatFen`
- **共享类型**：`api-client.ts` 导出 `GuestbookSummaryItem`（原内联类型），DashboardPage 与礼簿页卡片共用，消除重复定义

### P2

- **InviteModal 定时器按需启停**：原只要弹窗打开就每秒 `setNow`，改为有待接受邀请或刚生成邀请码时才启用（与首页 banner 同款修法）

- 删除确认文案"不可恢复"：已确认产品决策——礼簿管理不提供回收站（有收礼记录时后端阻断删除、空礼簿软删除后也无恢复入口，需恢复只能靠重新导入备份），文案与现状一致，无需改动

## 十一、手机端（窄屏）适配专项（同轮追加，375px 浏览器实测逐项验证）

### 1. 统计页人员往来排行

- 窄屏下「送/收/净」金额占满整行右对齐、折到姓名第二行；桌面端（≥640px）保持左右横排不变（`flex-wrap` + 金额容器 `w-full sm:w-auto`）

### 2. 人员详情收支汇总

- 三列统计卡 `text-2xl` 金额在 360px 屏溢出，改为 `text-lg sm:text-2xl` + `break-all`，桌面端不变

### 3. PageScaffold 页头

- **问题**：标题与操作按钮同行 `flex` 无换行，多按钮页（人员管理等）页头超出视口
- **修复**：窄屏（<640px）标题与按钮上下布局、按钮独占整行并 `flex-wrap`；桌面恢复左右横排。人员管理/批量编辑/礼簿详情/明细列表 4 页 actions 容器同步加 `flex-wrap`

### 4. 类别筛选芯片撑宽整页（人员管理 548px 溢出，含底导航被顶飞）

- **根因**：`RelationTagFilter` 芯片行 `overflow-x-auto` 位于纵向 flex 容器（筛选卡片）内，flex 子项默认 `min-width: auto = min-content`，内部 `shrink-0` 芯片的 min-content 约 700px，顶开滚动容器 → 整页被撑宽；`fixed` 底导航随布局视口变宽被顶出屏幕（导航本身各页公用、代码无差异）
- **修复**：按用户要求不做横向滚动，4 处芯片筛选条（人员类别 / 审批面板 / 家庭群组切换 / 通知类型）统一改为 `flex-wrap` 多行排列

### 5. 批量编辑页移动体验 + 主容器根治

- **批量编辑页**：表格 `min-w-[860px]` 在卡片内部横滑（页面不横滚）；卡片顶部新增提示「表格较宽，手机上可左右滑动编辑；如需批量修改多人，建议在平板或电脑浏览器中操作」；输入框手机端 16px（桌面 14px），兼顾可读性并避免 iOS 聚焦自动缩放
- **主容器根治（AppLayout `<main>`）**：批量编辑页最初仍整页 924px——`min-w-[860px]` 表格的宽度沿 flex 链一路 min-content 传播；且主容器 `mx-auto` 使 stretch 失效、宽度回退 fit-content，`min-w-0` 单独不生效。修复为 `w-full + min-w-0 + max-w-6xl`（宽度=视口、桌面居中不变），此后所有 `overflow-x-auto` 容器真正收住。4 处表格滚动容器（批量编辑/导入预览/用户管理/审计日志）补 `min-w-0` 加固
- **回归**：375px 实测批量编辑页、人员页均 375/375 零溢出；前端 180 条全部通过，TypeScript 类型检查通过
