# 2026-10-08 首页与登录页审查修复汇总

起因：对项目首页（登录后 `/` → DashboardPage）、登录页（LoginPage）和礼簿管理页（GuestbookPage）做了一轮审查，按 P1 → P3 优先级实施。遗留的"首页 N+1 请求"优化一并完成（复用既有批量接口，无需后端改动）。前端测试全绿（180 条），TypeScript 类型检查通过。

## 一、首页（DashboardPage）

### P1 正确性

- **日期边界移入组件**：原 `thisMonthStart` 等 4 个模块级常量在应用加载时计算一次，SPA 标签页常驻不刷新时跨月/跨年"本月、本年"汇总静默错位；已改为组件内 `useMemo` 按渲染时计算
- **金额统一 `formatFen`**：礼簿汇总原 `(total_amount / 100).toFixed(0)` 直接丢弃"分"位（¥123.45 显示成 ¥123），最近收款与日常记录也手写 `/100).toFixed(2)`；三处已统一走 `formatFen`（带负号处理）

### P2 体验

- **加载态解耦**：原 `gbLoading || dailyLoading` 任一未完成即整体替换为"加载中…"，统计卡片数据已返回也被挡住；改为各区块独立加载，统计卡片未就绪时显示占位"—"，两个列表各自显示加载态
- **空状态引导**：「暂无进行中的礼簿」「暂无记录」从纯文字改为带可点击的「＋ 新建礼簿」「＋ 记一笔」按钮
- **N+1 请求消除**：进行中的礼簿原逐个调用单簿 summary 接口（最多 3 次额外请求），改为一次 `GET /guestbooks/summaries` 批量查询（复用既有 `useAllGuestbookSummaries` hook），首页请求数从最多 8 个降到 6 个；协作邀请保持独立 30s 轮询不变

### P3 性能与无障碍

- **定时器空转**：`PendingInvitesBanner` 的 1 秒倒计时 interval 原在 `invites.length === 0` 时也在跑，改为按是否有邀请启停
- **移动端断点**：本月收支卡片原写死 `grid-cols-3`，窄屏拥挤；改为 `grid-cols-1 sm:grid-cols-3`
- **aria 补全**：邀请码输入框补 `aria-label` 与 `autoComplete="one-time-code"`；「合并」按钮补 `aria-label`（原仅有 `title`，移动端不可见）
- 补充说明：全局 `staleTime: 30s` 此前已配置，本次审查确认无需改动

## 二、登录页（LoginPage）

### P1

- **协议弹窗关闭按钮空白**：原代码中 ✕ 图标内容丢失，按钮渲染为不可见的空白区域；已补上 ✕ 与 `aria-label="关闭用户协议"`

### P2

- **弹窗无障碍**：补 `role="dialog"`、`aria-modal="true"`、`aria-label="用户协议"`，新增 Esc 键关闭

### P3

- **autoComplete**：用户名 `username`、密码框按登录/注册自动切换 `current-password` / `new-password`、确认密码 `new-password`、邮箱 `email`（`EmailSuggestInput` 新增 `autoComplete` 透传）
- **验证码输入**：两个验证码框限制纯数字输入、`inputMode="numeric"`（调出数字键盘）、`autoComplete="one-time-code"`、补 `aria-label`

## 三、礼簿管理页（GuestbookPage）

同一审查流程覆盖礼簿列表页与新建礼簿页，按 P1 → P3 实施。

### P1

- **Card 组件提取**：原 `Card` 定义在 `GuestbookListPage` 函数内部，每次渲染都产生新组件类型，React 卸载并重建所有卡片的 DOM 子树（hover 动画重置、状态丢失）。已提取为组件外的 `GuestbookCard`，删除/邀请/恢复回调以 props 传入
- **金额统一 `formatFen`**：卡片金额原手写 `toFixed(2)`（首页收敛时漏改的一处），已改用 `formatFen`
- **共享类型**：`api-client.ts` 导出 `GuestbookSummaryItem`（原内联类型），DashboardPage 与礼簿页卡片共用，消除重复定义

### P2

- **InviteModal 定时器按需启停**：原只要弹窗打开就每秒 `setNow`，改为有待接受邀请或刚生成邀请码时才启用（与首页 banner 同款修法）

### P3

- **aria 补全**：「合并」按钮补 `aria-label`（原仅 title）；邀请弹窗的查找输入框、协作起止 `datetime-local` 补 `aria-label`
- **移除 `setTimeout` 导航**：新建礼簿成功后原延迟 100ms 再跳转，但 Toast 属于本页组件、导航后即卸载，延迟反而引入卸载后 setState 风险，改为直接导航

### 审查确认无需改动项

- `useCollaborationInviteLogs(null)` 已有 `enabled` 控制，不发空请求
- 删除确认文案"不可恢复"：删除为软删除，但回收站未开发、无礼簿恢复端点，文案与现状一致
- 查找最少 3 字符与用户名/邮箱最短长度匹配，合理

## 四、审查确认无需改动项（首页 / 登录页）

- 登录页的内联错误字段定位、发送验证码 60s 倒计时与服务端节流一致、服务器不可达粘性 Toast 等既有处理
- 后端 `/guestbooks/summaries` 批量接口已存在且数据口径正确，直接复用
