## 第一部分：终端用户技术支持

## 1. 产品简介

礼云随笔是一款面向个人和家庭的轻量级礼金往来管理工具，覆盖完整的随礼生命周期：

- **日常记账**：记录每一次送出或收到的礼金，掌握人情往来差额，提醒回礼时机。
- **宴请收礼**：现场快速创建礼簿，支持多人同时用手机/平板记账，实时同步，确保账目安全。
- **合并归档**：宴席结束后通过合并向导建立人员关联，计算往来差额，礼簿长期保留可按宴请查看。
- **家庭共享**：创建家庭组，邀请家人共享数据，主账户审批确保数据质量。
- **双安全模式**：默认普通安全（零摩擦）；可选增强安全（客户端零知识加密，密钥不离开设备）。

支持手机、平板、电脑三端使用，支持离线记账和 PWA 安装到主屏。

## 2. 快速入门

### 2.1 首次使用

**第一个用户（超级管理员）：**
1. 打开应用，点击「没有账户？立即注册」
2. 输入用户名、密码、安全邮箱（1-2个）完成注册
3. 第一个注册的用户自动成为超级管理员（super_admin）
4. 进入首页，开始使用全部功能

**后续用户（一般用户）：**
1. 打开应用，点击「没有账户？立即注册」
2. 输入用户名、密码、安全邮箱完成注册
3. 注册后自动成为普通用户（user），可独立使用全部记账功能
4. 每个用户的数据完全隔离，互不可见

**进入首页后：**
- 看到本月/本年收支总览、快捷入口（记一笔、新建礼簿、加入协作）
- 点击「记一笔」即可录入第一条日常礼金记录

### 2.2 核心操作路径

**日常记账（3步完成）：**

1. 点击「记一笔」
2. 选择类型（送出去/收进来）、输入金额、选择对方人员
3. 点击「保存」

**创建礼簿并收礼：**

1. 点击「新建礼簿」→ 填写名称、事由类型、宴席日期
2. 进入收礼界面 → 输入宾客姓名、金额、选择收款方式
3. 点击「提交」完成一笔收礼

**多人协作收礼：**

1. 礼簿创建者生成协作码/二维码
2. 其他人在自己设备上输入协作码或扫码加入
3. 设置本终端记账员姓名后开始记账
4. 所有人录入的数据实时同步

## 3. 功能模块操作指南

### 3.1 日常礼金记录

**记录一条"送出去"的礼金：**

1. 进入首页 → 点击「记一笔」
2. 选择类型「送出去」
3. 输入金额（如 1000 元）
4. 选择对方人员（可从人员库选择或新建）
5. 选择事由类型（婚礼、生日、满月酒等）
6. 选择日期（默认今天）
7. 可选填备注
8. 点击「保存」

**记录一条"收进来"的礼金：**
步骤与"送出去"类似，额外可选择收款方式（现金/微信/其他）和收款账户。

**查看和编辑记录：**

- 在明细页可看到所有记录，按时间倒序排列
- 支持按类型、事由、日期范围筛选
- 点击某条记录可编辑金额、日期、事由等字段
- 删除记录需二次确认，删除操作会记入日志

### 3.2 礼簿管理与现场收礼

**礼簿的三个阶段：**

| 阶段 | 说明 | 可执行操作 |
| ------ | ------ | ----------- |
| 收礼中 | 宴席进行中，多人协作收礼 | 收礼记账、对账、多端同步 |
| 收尾中 | 宴席结束，补录与修正阶段 | 补录宾客、修正记录、合并向导 |
| 已归档 | 数据确认无误，锁定只读 | 仅查看和导出 |

**新建礼簿：**

1. 点击「新建礼簿」
2. 填写礼簿名称（如"张小明婚礼收礼"）
3. 选择事由类型（婚礼/寿宴/满月酒/乔迁/升学/丧葬/其他）
4. 选择宴席日期
5. 创建后自动进入「收礼中」状态

**现场收礼操作：**

1. 进入礼簿的收礼界面
2. 输入宾客姓名（支持从历史人员库联想）
3. 可选填电话号码
4. 输入金额
5. **必须选择收款方式**（现金/微信/其他，无默认值）
6. 选择收款账户（现金→选收银人；微信→选微信账户，默认带出终端预设）
7. 可选填备注（建议记录付款方微信昵称，便于对账）
8. 点击「提交」

**微信收款二维码：**

- 选择微信收款账户后，界面自动显示该账户的收款二维码
- 宾客可直接扫码付款
- 切换微信账户时二维码自动更换

**微信限额预警规则：**

- 每个微信账户可设置每日限额（默认 ¥200,000）
- 剩余额度 < ¥2,000 时：账户名标红警示
- 剩余额度 ≤ ¥200 时：账户置灰禁用，不可选择
- 录入金额超出剩余额度时：禁止保存并弹出警告

**结束宴席（进入收尾）：**

1. 确认宴席结束 → 礼簿进入「收尾中」状态
2. 多端协作会话自动关闭
3. 自动弹出合并向导（可选择执行或跳过）

**归档礼簿：**

- 收尾阶段确认所有数据无误后，手动标记为「已归档」
- 归档后锁定为只读，不可修改

**收尾期补录：**

- 宴席结束后宾客事后补礼，可在收尾阶段继续新增记录
- 支持手动设置记账时间（精确到秒）

### 3.3 终端设置

每个参与协作的设备（终端）需要独立设置：

**设置记账员（操作者）：**

- 首次进入收礼界面前，必须设置记账员姓名
- 该姓名将记录在操作日志中，用于追溯

**设置默认收款人：**

- 每个终端可独立设置默认现金收银人和默认微信账户
- 收礼时自动带出预设的收款人，减少操作步骤
- 收礼过程中可随时切换，也可重新设置默认值

**示例：**

- 张三的手机：记账员「张三」、默认现金「张三」、默认微信「李四-微信」
- 李四的手机：记账员「李四」、默认现金「王五」、默认微信「李四-微信」

### 3.4 代理送礼（批量收礼）

当一人为多人随礼时使用（如"我替全家随礼"）：

1. 进入代理送礼页面
2. 可选填经办人（代理人）姓名
3. 逐一添加被代理人（数量不限）
4. 选择支付方式：
   - 统一设置：所有被代理人用同一种支付方式
   - 分别设置：每个被代理人可单独选择支付方式和金额
5. 查看合计人数和合计金额
6. 点击「批量提交」→ 一次性生成多条独立记录

**注意：** 被代理人的记录与普通收礼记录等级完全相同，独立存在，不附属于代理人。

### 3.5 多人协作收礼

**创建协作：**

1. 在礼簿中点击「多人协作」或「加入协作」
2. 系统生成协作码和二维码
3. 将协作码/二维码分享给参与记账的亲友

**加入协作：**

1. 在自己的设备上打开应用
2. 输入协作码或扫描二维码
3. 设置本终端的记账员姓名
4. 设置默认现金收银人和微信账户
5. 开始记账

**同步机制：**

- 使用 WebSocket 实时同步，任一终端新增记录后其他终端 5 秒内可见
- 网络中断时本地暂存，恢复后自动同步
- 每笔记录有全局唯一 ID（UUID），防止重复写入

**退出协作：**

- 任何终端可主动退出协作
- 礼簿进入收尾阶段时自动关闭协作会话

### 3.6 对账管理

对账是收银员与记账人之间的账目核对，贯穿收礼全过程（不是一次性收尾动作）。

**发起对账：**

1. 在礼簿详情页切换到「对账」Tab
2. 或在收礼界面点击对账快捷入口

**对账流程：**

1. 筛选查看：可按收银员（现金/微信）、记账员筛选
2. 收银员清点实收金额，与账面金额核对
3. 核对无误后，勾选记录 → 点击「标记为已对账」
4. 已对账记录显示绿色对勾标识

**对账进度：**

- 顶部显示：已对账 X 笔 / 总 Y 笔，金额已对账 ¥A / 总 ¥B
- 进度条直观显示对账完成度

**取消对账：**

- 已标记为「已对账」的记录可随时取消标记
- 取消后恢复为「未对账」状态，可重新核对

**发现差异时：**

- 可标记记录为「待核实」
- 发现漏记时，记账人可补记（支持手动设置记账时间）

**对账提示：**

- 收礼界面常驻显示未对账记录数量
- 未对账超过 20 笔时显示对账建议（不弹窗、不阻断操作）

### 3.7 合并向导

礼簿进入收尾阶段后，系统自动弹出合并向导，将礼簿中的宾客与人员库建立关联。

**合并步骤：**

1. **确认合并礼簿**：选择要合并的礼簿
2. **人员映射**：系统为每位宾客推荐匹配的人员
   - 电话+姓名完全匹配 → 自动关联
   - 姓名完全一致 → 推荐匹配（需确认）
   - 同音字（如"张峰"↔"张锋"）→ 推荐匹配（需确认）
   - 别名匹配 → 推荐匹配（需确认）
   - 无匹配 → 可选择「新建人员」
3. **合并预览**：查看所有映射关系
4. **执行合并**：确认后建立 person_id 关联

**重要说明：**

- 合并操作不搬迁数据，收礼记录始终保留在礼簿中
- 合并后在人员详情页可查看包含该礼簿在内的完整往来差额
- 合并后 7 天内可撤销
- 已匹配过的人员下次不会重复推荐

### 3.8 人员管理

**人员档案包含：**

- 姓名、称谓/昵称、关系标签、电话号码、历史别名、备注

**关系标签：** 亲戚、朋友、同事、同学、邻居、其他

**查看往来明细：**

- 点击某人员 → 查看与该人的所有礼金记录
- 包含日常记录和已关联的礼簿记录，按宴请分组展示
- 顶部汇总：总送出、总收到、净差额

**按宴请查看：**

- 人员详情页展示该人员参与的所有宴请列表
- 显示礼簿名称、事由、日期、金额
- 点击可跳转到对应礼簿详情

**差额调整：**

- 可手动输入正负数金额调整差额（如双方已口头平账）
- 需填写原因备注
- 展示为「系统计算差额 + 手动调整 = 最终差额」

**人员合并：**

- 误建重复人员时，支持合并并迁移所有关联记录

### 3.9 统计与报表

- **年度汇总**：按年度统计送出/收到的总金额
- **收支差额总览**：总送出 - 总收到 = 净差额
- **礼簿专项统计**：按礼簿维度统计收礼情况
- **账户对账报表**：导出各账户明细，用于与实际收款对账
- **微信对账辅助**：导出含备注（付款微信昵称）的记录列表
- **对账进度报表**：展示各账户对账完成度

### 3.10 数据导入导出

**数据导出：**

- 支持导出为 Excel / CSV 格式
- 可导出全部数据（含操作日志）
- 可单独导出某个礼簿（独立文件，方便交给主人家存档）

**数据导入：**

1. 下载导入模板（「日常记录模板」或「礼簿记录模板」）
2. 按模板格式填写数据
3. 上传文件 → 系统展示预览列表
4. 校验失败的行高亮标红并说明原因
5. 确认无误后写入

**日常记录模板字段：** 姓名、电话、类型(收/送)、金额、事由、支付方式、日期、备注

**礼簿记录模板字段：** 礼簿名称、事由类型、宴席日期、宾客姓名、电话、金额、支付方式、收银人、记账时间、备注

**数据备份：**

- 支持手动备份
- 支持自动定期备份提示

### 3.11 家庭共享

**创建家庭组：**

1. 在设置中选择「创建家庭组」
2. 设置家庭组名称
3. 系统生成邀请码（有时效限制）
4. 将邀请码分享给家人

**加入家庭组：**

1. 在设置中选择「加入家庭组」
2. 输入邀请码
3. 加入后即可看到家庭共享数据

**权限说明：**

- **主账户**：完整读写权限 + 审批权，可邀请/移除成员
- **家庭成员**：可查看家庭共享池中的非隐私数据；可提交新增和修改，但需主账户审批后才正式生效
- **「隐私记录」**：同步至云端但仅标记者本人可查看，其他家人不可见；统计合计中仅本人能看到包含隐私数据的汇总

**审批机制：**

- 家人提交的新增/修改记录进入「待审批」队列
- 主账户可逐条或批量审批
- 审批通过后记录正式生效

### 3.12 安全模式

**普通安全模式（默认）：**

- 开箱即用，无需任何额外操作
- 传输加密（TLS）+ 服务端加密 + 隐私记录权限隔离
- 适合绝大多数用户

**增强安全模式（可选）：**

- 客户端 AES-256-GCM 零知识加密
- 加密密钥仅存储在你的设备上，永不上传服务端
- 服务端无法解密你的数据，实现真正的零知识保护
- 适合对数据隐私有极高要求的用户

**开启增强安全模式：**

1. 进入设置 → 安全模式 → 选择「增强安全」
2. 系统自动生成加密密钥
3. **重要**：系统会显示一组恢复助记词（12 或 24 个词），请务必离线抄录保存在安全的地方
4. 助记词是恢复数据的唯一凭证，丢失助记词 = 丢失所有数据

**恢复助记词注意事项：**

- 助记词不会上传到服务端
- 换设备时需要输入助记词恢复密钥
- 建议抄录在纸上，存放在安全的地方（如保险箱）
- 不要截图保存、不要存在云端笔记中

**家庭共享与增强安全：**

- 增强模式下启用家庭共享时，系统采用密钥分层机制
- 主账户生成家庭主密钥，用每位成员的个人密钥加密后分发
- 成员加入时接收加密的家庭主密钥，退出时自动撤销

**加密导出：**

- 增强模式下导出的数据文件是加密的
- 需要使用你的密钥才能打开
- 普通模式下导出为标准 Excel/CSV 文件

## 4. 重名提醒弹窗说明

当收礼录入的宾客姓名与礼簿中已有记录重名时，系统会弹出提醒窗口：

**弹窗内容：**

- 显示已有的同名记录详情（姓名、金额、支付方式、时间）
- **「备注已有记录」输入框**：预填原记录的备注，修改后保存时覆盖
- **「备注当前记录」输入框**：预填当前录入的备注，修改后保存时覆盖

**三个操作按钮：**

1. **新增记录**：保存当前录入为新记录（两条记录并存）
2. **取消录入并编辑原记录**：关闭弹窗，跳转到原记录的编辑页面
3. **取消录入**：放弃当前录入，关闭弹窗

**说明：** 两个备注输入框的内容如果修改过，保存时会分别替换对应记录的备注。如果未修改，则保持原样。

## 5. 常见问题（FAQ）

### Q: 数据存在哪里？安全吗？

A: 数据默认存储在你设备的本地（IndexedDB），日常记录不会自动上传到云端。加入家庭组后，数据才会按需同步到服务端。服务端采用 TLS 传输加密和服务端静态加密。如果你开启了增强安全模式，数据在上传前会先在设备上加密，服务端完全无法读取你的数据。

### Q: 没有网络能记账吗？

A: 可以。应用支持离线使用，所有操作在本地完成。网络恢复后自动同步。

### Q: 多人同时记账会不会冲突？

A: 每笔记录有全局唯一 ID，不会重复写入。如果出现同名同金额的疑似重复，系统会自动标记让你确认。

### Q: 微信收款额度用完了怎么办？

A: 当某个微信账户剩余额度 ≤ ¥200 时，系统会自动禁用该账户并提示切换。建议提前设置多个微信收款账户。

### Q: 宴席结束了还能补录吗？

A: 可以。礼簿进入「收尾中」状态后仍可补录宾客（如事后补礼），支持手动设置记账时间。

### Q: 礼簿归档后还能修改吗？

A: 不能。归档后礼簿锁定为只读。请在归档前仔细核对所有数据。

### Q: 如何与家人共享数据？

A: 在设置中创建家庭组，生成邀请码分享给家人。家人加入后可查看共享数据。家人新增或修改记录需要你（主账户）审批。

### Q: 「隐私记录」是什么意思？

A: 任意记录都可以标记为「隐私记录」。标记后数据仍会同步到云端（作为备份），但只有你本人能看到，家庭成员无法查看。统计合计中也只有你能看到包含隐私数据的汇总。

### Q: 增强安全模式下忘记密码/丢失助记词怎么办？

A: 很遗憾，如果没有助记词或密钥备份，加密的数据将无法恢复。这就是为什么在开启增强模式时，系统会强制引导你保存助记词。请务必妥善保管。

### Q: 普通安全模式和增强安全模式可以随时切换吗？

A: 可以。在设置中随时切换。从普通切换到增强时，系统会引导你生成密钥和保存助记词。

### Q: 金额为什么输入的是"分"？

A: 系统内部以"分"为单位存储金额（避免浮点精度问题），但在界面上会显示为"元"。你输入和看到的都是"元"，无需手动转换。

### Q: 如何导出礼簿数据给主人家？

A: 在礼簿详情页选择「导出」，可将单个礼簿导出为独立文件。

### Q: 对账是什么意思？

A: 对账是收银员（管钱的人）和记账人（录入记录的人）之间的核对。比如张三负责收现金，李四负责记账，宴席中途张三清点手中现金后，与李四录入的账面金额进行核对，确保没有错记漏记。

### Q: 代理送礼和被代理人是什么关系？

A: 代理送礼就是一人替多人随礼的场景。比如赵大伟替全家随礼，他作为经办人，添加妻子、父亲、同事作为被代理人。每个被代理人的记录都是独立的，与普通收礼记录完全相同。

## 6. 故障排查

### 6.1 同步问题

#### 症状：其他设备看不到最新记录

- 检查网络连接是否正常
- 查看同步状态指示器（显示"同步中"或"离线"）
- 尝试手动触发同步
- 确认所有设备加入了同一个协作会话

#### 症状：同步状态一直显示"同步中"

- 检查网络是否稳定
- 尝试退出协作后重新加入
- 如果数据量大，全量同步可能需要较长时间

### 6.2 数据问题

#### 症状：数据丢失

- 检查是否在正确的设备上查看（数据默认存本地）
- 如果加入了家庭组，检查云端是否有备份
- 检查是否有可用的备份文件
- 如果开启了增强安全模式，确认密钥/助记词是否正确

#### 症状：导入数据失败

- 确认使用了正确的导入模板
- 检查必填字段是否完整
- 检查金额格式是否正确（正整数）
- 查看校验失败行的错误说明

### 6.3 收礼问题

#### 症状：无法提交收礼记录

- 确认已选择收款方式（无默认值，必须手动选择）
- 确认已输入宾客姓名和金额
- 如果选择微信收款，检查账户是否已超限（≤ ¥200 会被禁用）
- 如果录入金额超出账户剩余额度，系统会禁止保存

#### 症状：微信收款二维码不显示

- 确认微信账户已上传收款二维码图片
- 在账户管理中上传二维码后重试

### 6.4 家庭共享问题

#### 症状：家人看不到我的数据

- 确认数据已同步到云端（检查同步状态）
- 确认家人已正确加入家庭组
- 如果记录标记为「隐私记录」，家人不可见（这是预期行为）

#### 症状：家人提交的修改没有生效

- 家人提交的修改需要主账户审批后才生效
- 在「待审批」队列中查看并审批

### 6.5 增强安全问题

#### 症状：切换到增强模式后数据看不到了

- 确认密钥是否正确生成/导入
- 如果使用助记词恢复，检查输入是否正确
- 确认在正确的设备上操作（密钥绑定设备）

#### 症状：换设备后数据无法解密

- 需要使用助记词在新设备上恢复密钥
- 或通过密钥导入功能导入之前备份的密钥

## 9. 代码规范

### 9.1 前端规范

- TypeScript strict mode，所有变量和函数必须有类型标注
- 组件使用函数式组件 + Hooks
- 使用 TanStack Router 的编译时类型安全路由，不使用运行时路由字符串
- TanStack Query 管理服务端状态，Zustand 管理客户端状态
- Tailwind CSS 4 使用 CSS-first 配置（@theme 指令），不生成 tailwind.config.js
- ESLint 9 (flat config) + Prettier 统一代码风格
- 包管理使用 pnpm，不使用 npm 或 yarn

### 9.2 后端规范

- 全异步模式：AsyncSession + asyncpg
- 分层架构：API 路由 → Service 业务逻辑 → ORM 数据访问
- Pydantic v2 模型用于请求/响应校验
- ENUM 类型统一改为 VARCHAR + 应用层 Literal 校验（不使用数据库 ENUM）
- 所有金额以"分"（Integer）存储，前端展示转换为"元"
- Ruff 统一 Python 代码格式（替代 flake8/black/isort）
- 包管理使用 uv，不使用 pip
- **时间存储约定**：所有 DateTime 字段以无时区 UTC 入库（`app.core.time.utcnow`）。凡是按"某一天"过滤/聚合的接口，必须先把本地日期换算成 UTC 时间范围再查询（参考 `payment_accounts.received_today` 的写法），禁止直接用本地 `datetime.combine` 与 UTC 时间比较，否则跨时区/午夜边界会漏数

### 9.3 通用规范

- 所有业务表包含 owner_id 外键关联 users.id，API 层通过 JWT 自动过滤
- 操作日志不可修改、不可删除
- 关键操作（删除、合并）需二次确认
- 隐私记录（is_private）同步云端但仅本人可查看

### 10.2 关键设计决策

- **金额单位**：所有金额以"分"（Integer）存储，避免浮点精度问题。前端展示时除以 100 转换为"元"。
- **礼簿状态**：三态流转（active → closing → archived），所有转换由用户手动控制，不设自动过期。
- **合并语义**：合并操作不搬迁数据，gb_record 始终保留在礼簿中，仅建立 person_id 关联。
- **UUID 防重复**：每条 gb_record 有全局唯一 uuid 字段，防止多客户端重复写入。
- **同步字段**：daily_record、gb_record、person 表均含 is_private（隐私标记）和 sync_version（增量同步版本号）。
- **数据隔离**：所有业务表含 owner_id，API 层通过 JWT 中的 user_id 自动过滤。
- **时间存储**：所有 DateTime 字段以无时区 UTC 入库；按天统计类查询必须把本地日期换算为 UTC 范围（`received-today` 曾因此出现午夜漏数的线上 bug，回归测试见 `test_received_today_boundary_uses_local_date`）。
- **用户 ID**：格式为创建年份（4 位）+ 6 位流水号（如 2026000001），由 `app.core.user_id.generate_user_id` 生成；流水号按年递增，并发冲突自动重试。
- **角色体系**：仅三种——一般用户(user)、系统管理员(admin)、超级管理员(super_admin)。注册用户一律为一般用户；系统首个注册用户自动成为超级管理员；系统管理员由超级管理员通过管理后台"授权/直接创建"产生，超级管理员账户受保护（不可被改角色、禁用或删除）。

## 13. 常见开发问题

### Q: 为什么不用数据库 ENUM 类型？

A: PostgreSQL 的 ENUM 类型修改需要 DDL 操作（ALTER TYPE），在迁移中容易出错。统一使用 VARCHAR + 应用层 Literal 校验，更灵活且迁移友好。

### Q: 为什么金额用"分"存储？

A: 避免浮点精度问题。JavaScript 和 Python 的浮点数运算可能产生精度误差（如 0.1 + 0.2 ≠ 0.3）。使用整数"分"可以完全避免这个问题，前端展示时除以 100 即可。

### Q: 为什么合并操作不搬迁数据？

A: 礼簿是事件维度的长期记录，需要保留"某次宴请收了哪些礼"的完整信息。如果搬迁到日常记录，就丢失了宴请维度的上下文。合并只是建立 person_id 关联，使人员详情页能计算包含该礼簿的完整差额。

### Q: 现场协作和家庭云端同步有什么区别？

A: 现场协作是临时的 WebSocket 实时同步，范围是单个礼簿，宴席结束后关闭。家庭云端同步是长期的 HTTPS 增量同步，范围是全量数据，家庭组存续期间有效。两者的协议、数据范围、生命周期、冲突处理方式都不同。

### Q: 隐私记录（is_private）和增强安全模式是什么关系？

A: 隐私记录是普通安全模式下的功能，通过服务端权限隔离实现——数据同步到云端但只有标记者能查看。增强安全模式是更高层级的保护——数据在客户端加密后上传，服务端完全无法解密。两者可以叠加使用：增强模式下隐私记录同时享有客户端加密 + 服务端权限隔离的双重保护。

### Q: 前端状态管理怎么分工？

A: TanStack Query 管理服务端状态（API 数据、缓存、同步、乐观更新等），Zustand 管理客户端状态（终端设置、UI 状态、临时表单数据等）。不要用 Zustand 缓存可以从 TanStack Query 获取的数据。

### Q: 离线时数据怎么处理？

A: IndexedDB（Dexie.js）是主存储。离线时所有操作写入 IndexedDB，网络恢复后通过 sync_version 字段进行增量同步。TanStack Query 的 persistQueryClient 配合实现离线缓存。

### Q: 增强安全模式下，服务端还能做搜索/排序/统计吗？

A: 不能。增强模式下服务端存储的是密文，无法进行服务端搜索、排序、统计。所有查询必须在客户端解密后进行。本项目的数据量（数万条记录）下，客户端解密和查询的性能影响可以忽略不计（Web Crypto API 使用硬件加速的 AES-GCM）。
