### 2.3 硬性约束

1. **全异步 ORM：** 所有数据库操作通过 SQLAlchemy 2.0+ async ORM（`AsyncSession`），禁止 `text()` 原生 SQL，禁止 `connection.execute()` 直接操作
2. **金额用分：** 所有金额字段使用 INTEGER（单位：分），前端展示时转换为元（÷100）
3. **类型标注：** 所有函数必须有完整的 type hints，参数使用 `Annotated` 风格
4. **数据隔离：** 所有业务查询必须带 `owner_id` 过滤（从 JWT token 中提取 `user_id`），确保用户间数据完全隔离 ⚠️ **[P0 待实现 — 当前代码尚未添加 owner_id]**
5. **幂等写入：** 收礼记录创建使用 UUID 幂等键，防止多客户端网络重试导致重复
6. **审计日志：** 收礼记录的新增/编辑/删除必须写入 operation_log，日志不可修改不可删除
7. **密码安全：** 密码使用 Argon2 哈希（不用 bcrypt），管理员不可重置用户密码，仅用户通过安全邮箱自行重置
8. **禁用数据库 ENUM：** 所有枚举字段使用 VARCHAR + 应用层 Literal 类型校验，不使用数据库原生 ENUM 类型
9. **软删除：** 业务表使用 `is_deleted` + `deleted_at` 字段（30 天 purge），不使用物理删除

### 2.4 开发模式

```text
收到需求 → 确认里程碑 → 确认涉及的 Model → 编写/更新 Schema → 编写 API 路由（async） → 编写/更新 Alembic 迁移 → 验证 → 更新技能文件标注
```

**核心设计原则：**

### 3.4 硬性约束

1. **TypeScript 严格模式** — 禁止 `any` 逃逸，所有 API 响应必须有类型定义
2. **服务端状态** — 当前裸 fetch + useState ✅，目标 TanStack Query 5 🎯（需先安装 `@tanstack/react-query`）
3. **路由** — 当前 react-router-dom v7 ✅，目标 TanStack Router 🎯（需迁移）
4. **Tailwind 优先** — 样式使用 Tailwind CSS 4 原子类，遵循 UI 设计规范的 token 值（CSS-first @theme 配置）
5. **状态分层** — 服务端状态用 TanStack Query（目标），局部 UI 状态用 `useState`，跨组件/全局客户端状态用 Zustand store
6. **金额显示** — 后端返回分（Integer），前端统一转换为元展示（÷100，保留两位小数）
7. **PWA 兼容** — 确保离线场景下的降级体验，关键数据本地缓存（目标 Dexie.js 🎯）
8. **响应式适配** — 手机竖屏（<640 单列）、平板（640-1280）、桌面（≥1280）
9. **状态标注检查** — 开发前必须检查技能文件中的 `[已实现]/[待实现]` 标注，避免 import 不存在的包

### 6.2 知识体系

**必读文档：**

- `礼尚云-需求分析.md`（v4.1）模块四（F-4.1 ~ F-4.9）— 多客户端同步

**核心机制：**

| 机制 | 说明 |
| ------ | ------ |
| 协作码 | 礼簿创建者生成，其他终端扫码/输入码加入 |
| 终端绑定 | 加入后必须设置记账员，才可开始记账 |
| 实时推送 | 任一终端新增记录，其他终端 5 秒内可见 |
| 离线暂存 | 断网时本地队列暂存，恢复后按时间戳重放 |
| 冲突仲裁 | 时间戳 + 客户端标识，同名同金额标记"疑似重复" |
| UUID 防重 | 每条记录携带全局唯一 ID，客户端生成，防止重复写入 |
| 会话超时 | 已完成礼簿的协作会话 7 天后自动清理 |

### 6.3 硬性约束

1. **最终一致性** — 不要求强一致性，但必须保证所有终端最终数据一致
2. **离线优先** — 断网时核心收礼功能不受影响，数据不丢失
3. **心跳检测** — WebSocket 连接必须有存活检测，断线自动重连
4. **幂等重放** — 离线队列重放时，通过 UUID + 幂等键保证不产生重复记录
