## 一、系统设置页

### 当前用户卡片重构（原"本终端信息" + "个人资料"合并）

- 移除无展示价值的"终端标识"输入框（clientId 内部同步逻辑保留，仅不再展示）
- 新增**用户 ID**、用户名（只读，标签与内容同一排显示，无框无底纹）、角色（中文徽章）
- 原"个人资料"卡片（昵称、自动锁定时间、保存资料）并入，页面减少一张卡片
- 角色中文标签统一为：一般用户 / 系统管理员 / 超级管理员
- 涉及文件：`web/src/pages/SettingsPage.tsx`

### 账户安全卡片：内联红字错误

- 修改密码时当前密码错误，红字提示显示在输入框正下方，输入框边框同步变红；输入任意内容自动清除
- 其他类型错误（网络失败等）仍走 Toast
- 新增测试：`web/src/test/ChangePasswordSection.test.tsx`（4 条用例）

## 二、登录页

### 内联红字错误（全表单推广）

- 登录失败（用户名或密码错误等）→ 密码框下方红字 + 红边框，取代原顶部横幅
- 注册校验错误按字段归属内联显示：
  - 两次密码不一致 → 确认密码框下方
  - 缺少主/备用邮箱验证码 → 对应验证码框下方
  - 未同意用户协议 → 协议勾选行下方
  - 注册接口错误（如用户名已存在）→ 用户名输入框
  - 发送验证码失败 → 对应验证码框下方
- 任一字段输入即清除错误提示与红边框
- 实现：`errorField` 字段归属机制（`web/src/pages/LoginPage.tsx`）
- 新增测试：`LoginPage.test.tsx` 内联错误 describe 块（6 条用例）

### 密码框改用原生眼睛图标

- 删除登录页/注册页密码框的自定义眼睛切换按钮，恢复 `type="password"`，由 Edge/Chrome 原生控件提供可见性切换（Firefox 无原生控件）
- 关键修复：全局 CSS 中 `input[type='password']::-ms-reveal { display: none }` 已删除——该样式是为配合旧自定义眼睛按钮加的，隐藏了原生图标
- 影响范围：全站密码框（登录、注册、设置页、注销确认）统一获得原生眼睛

## 三、用户 ID 规则

- **新格式**：创建年份（4 位）+ 6 位流水号，如 `2026000001`；流水号按年递增，同年上限 999999
- **生成模块**：`server/app/core/user_id.py`（`generate_user_id` + `add_user_with_generated_id`，并发唯一键冲突自动重试 3 次）
- **接入点**：注册接口、管理员创建用户、数据导入创建管理员
- **存量迁移**：`alembic f7g8h9i0j1k2_m6_user_id_year_seq`
  - 老用户按 `created_at` 年份重排（同年按创建顺序从 1 编号）
  - 先临时删除 17 个引用 `users.id` 的外键约束 → 更新全部子表 → 更新主键 → 按原名重建（保留 CASCADE / SET NULL 语义）
  - 同步 `users_id_seq` 序列；迁移幂等可重复执行
- **注意**：迁移后旧登录令牌失效，需重新登录
- 新增测试：注册返回 ID 必须落在当年 `年份×1000000` 区间

## 四、角色体系（3 级落地，原 5 级方案废止）

| 角色 | 标识 | 来源 |
| --- | --- | --- |
| 一般用户 | `user` | 注册用户一律为此角色 |
| 系统管理员 | `admin` | 超级管理员授权（一般用户升级）或直接创建 |
| 超级管理员 | `super_admin` | 系统首个注册用户自动产生 |

**后端**（`server/app/api/admin.py`、`schemas/auth.py`）：

- `RoleType = Literal["super_admin", "admin", "user"]`；管理接口角色参数仅接受 `admin | user`
- 只有超级管理员可以：授权/收回系统管理员、直接创建系统管理员（其他人 403）
- 超级管理员账户受保护：不可改角色、不可禁用、不可删除（400）
- 注册逻辑不变：首个用户 super_admin，其余一律 user

**前端**：

- 角色类型收敛为三值（`auth.ts`、`types/index.ts`），中文标签全局统一
- 管理后台新建用户：角色下拉仅 一般用户 +（超级管理员可见的）系统管理员
- 用户列表新增"设为系统管理员 / 降为一般用户"按钮（仅超级管理员可见，超级管理员行不显示）

**存量迁移**：`alembic g8h9i0j1k2l3_m7_normalize_user_roles` 将 `family_member` / `collaborator` 等遗留值归位为 `user`；礼簿级协作权限由 `collaboration_invites` 承载，不再依赖用户角色。

## 五、时区约定与 Bug 修复

- **约定**（已写入 `docs/AI-support.md` §9.2 / §10.2）：所有 DateTime 以无时区 UTC 入库（`app.core.time.utcnow`）；按天过滤/聚合的接口必须先把本地日期换算成 UTC 时间范围再查询
- **Bug 修复**：`payment_accounts.received-today` 原用本地 `datetime.combine` 直接与 UTC 存储的 `record_time` 比较，本地零点过后（UTC 仍在前一天）当天收款统计恒为 0，微信每日限额判断随之出错
- **修法**：查询边界经 `astimezone(timezone.utc)` 换算
- **回归测试**：`test_received_today_boundary_uses_local_date`——本地零点整与前一秒各造一条记录，断言只有零点整计入当天（非 UTC 时区下旧代码必挂）
