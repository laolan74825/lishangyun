## 产品 Bug 修复

### 解散家庭组必然 500（严重）

- **现象**：解散有成员的家庭组时，ORM 发出 `UPDATE family_members SET family_group_id=NULL`，触发 NOT NULL 约束，接口必然 500
- **修复**：`FamilyGroup.members` 关系加 `passive_deletes=True`，删除交由数据库已有的 `ON DELETE CASCADE` 外键处理（`app/models/family_group.py`）
- **附带清理**：`app/api/authorization.py` 中残留的 6 处 `[DEBUG]` 调试 print

### WS 消息类型不匹配（实时更新失效）

- **现象**：前端监听 `update_record`/`delete_record`，后端广播 `record_updated`/`record_deleted`，他人编辑/删除记录的实时更新完全不生效
- **修复**：统一为后端命名；`appStore` 新增 `updateGbRecord`/`removeGbRecord`；WS 客户端补齐处理分支

## 安全修复

### WebSocket 房间越权订阅（高危）

- `/ws/guestbooks/{id}` 原先只校验登录态，任意登录用户可订阅他人礼簿的实时记账广播并伪造记录事件
- 现增加礼簿所有权校验（与 HTTP 接口 `owner_id == current_user.id` 口径一致），未授权连接以 4003 关闭
- 顺带重构：`ws.py` 通过依赖注入获取数据库会话，不再绕过 `get_db`（此前测试的数据库覆盖对 WS 路由不生效）
- 前端对 4001/4003 不再无限重连

### 密钥配置启动校验

- 新增 `validate_security_settings()`：`SECRET_KEY` 为默认值、`APP_ENCRYPTION_KEY` 为全零默认或非法十六进制时，**生产环境直接拒绝启动**，开发环境仅告警
- `docker-compose.yml` 的 api 服务默认 `ENVIRONMENT=production`，忘配密钥会明确报错而非带全零 AES 密钥运行
- 新增 `tests/test_config_security.py` 覆盖 5 种密钥组合

### 登录防爆破

- 新增 `app/core/rate_limit.py`：内存滑动窗口，同一用户名在 `LOGIN_LOCK_MINUTES`（默认 10 分钟）内连续失败 `LOGIN_MAX_ATTEMPTS`（默认 5 次）即临时锁定，窗口过后自动解锁，登录成功计数清零
- 锁定期内即使密码正确也返回 429 并提示剩余等待时间

### 其他

- 验证码生成从非加密安全的 `random` 改用 `secrets`（注册、重置密码、安全邮箱三处）
- 邮件发送失败不再把 SMTP 异常原文返回客户端（改记服务端日志）
- 移除未使用的 `xlsx@0.18.5` 依赖（存在 CVE-2023-30533，npm 版已停更；导入导出实际走服务端 openpyxl）

## 测试基建整改

### 事件循环绑定问题（系统性根因）

- `pytest.ini` 的 `asyncio_default_fixture_loop_scope` 由 `session` 改为 `function`：fixture 与测试函数必须在同一事件循环，否则 asyncpg 连接跨循环复用会报 `another operation is in progress` 或整文件永久挂起
- 一处测试改为 `await db_session.refresh(n)`，避免在 ORM 绿色上下文外访问过期属性触发 `MissingGreenlet`

## 遗留事项（未处理，按优先级）

- docker-compose 的 web 服务用 `npm install` 构建 pnpm 项目，锁文件不可复现，应改用 corepack/pnpm
- 邮箱验证码有效期仅 1 分钟且无尝试次数限制，建议放宽至 5–10 分钟并加上限

- 仓库根目录仍有照片修复脚本等杂物文件（`colorize_photo.py`、`original_photo.jpg` 等），建议移出
